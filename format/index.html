Chapter reads public GitHub repositories containing Markdown books. Keep the structure familiar, the chapters ordered, and the images close to the text.

The book lives in book/

Create a book/README.md index with the book title as its first heading, a short description, and relative links to your volumes. Add chapter files under book/volumes/. You can choose a different root folder when importing.

Give each chapter an identity

Begin each chapter with YAML front matter between --- lines. Keep its slug stable when updating the book so bookmarks and reading progress can follow the chapter.

---
book: The Curious Learner's Book
volume: 1
volume_title: Foundations
chapter: 1
title: A place to begin
slug: a-place-to-begin
status: complete
summary: ../../_ai/chapter-summaries/001-a-place-to-begin-summary.md
---

# A place to begin

Your chapter starts here.
FieldPurpose
volume, chapterPositive integers determine reading order. Chapter numbers must be unique within each volume.
volume_titleUse the same title for every chapter in a volume.
titleShown in contents and search. A first-level Markdown heading can supply it if omitted.
slugA unique, lasting chapter identity. The file path is used if omitted.
statusUse planned, in-progress, review, or complete. Incomplete material is allowed and shown as an import warning.
book, summaryUseful authoring context. Reading titles come from the book index; summaries are kept outside reading chapters.

Numbered directory and file names can supply missing volume and chapter numbers. Explicit metadata is clearer. The reader ignores volume indexes, files with names starting with _, and material under book/_ai/.

Make it travel well

Use relative Markdown links for other chapters and heading anchors. Store images in the repository and reference them with relative paths. Chapters, Markdown indexes, and local images are downloaded from one fixed commit before a book becomes available on your shelf.

Write a little, keep your place

The authoring toolkit generates a repository scaffold and prompts for outlining, writing, continuing, checking sources, exercises, review, and publication. Use them with the AI tool of your choice.

Keep the agreed learning journey in SKELETON.md, writing instructions in AI_AUTHORING_GUIDE.md, and handoffs under book/_ai/. Update each chapter summary and CONTINUATION_STATE.md after a writing session: record what was actually written, open questions, verified sources, and the exact next section.

Publish, check, read

Publish the repository publicly on GitHub. In the authoring toolkit, validate its URL to check metadata, chapter order, internal links, and local images. Then add it to your library. You can choose a branch and book folder; each saved edition records its exact commit.
